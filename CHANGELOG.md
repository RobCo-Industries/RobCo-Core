# Changelog

## Unreleased

- The nightly run keeps no card it did not boot. `tools/nightly/boot_card.py` boots a snapshot copy of each packed card in its card job and checks the stage markers in order: the terminal card up to the UOS login screen on `raspi2b`, the Pip-Boy card up to the ROM's ready line on `raspi0`. The card is uploaded only when the boot passed and the card still matches `SHA256SUMS`.
- `tools/nightly/pack_card.py` fails closed. A folder with starting cluster 0, a chain that ends early or runs long for its size, a cluster out of range or used twice, a long name with no short entry, an invalid short name, a stray volume label bit, a FAT32 root cluster of 0 and FAT copies that differ now fail the job. Before, it skipped some of them in silence.
- The nightly run, `.github/workflows/nightly.yml`: every night it builds the five siblings at their default heads on their own library pins, packs the terminal and Pip-Boy cards and runs the whole-chain tests on four boards. `tools/nightly/plan.py` resolves the commits and image tags into one record per built repository, which the matrices, the summary and `VERSIONS.txt` all read, so the Pip-Boy row names the library and tag of the Pip-OS head it builds on, `tools/nightly/junit_gate.py` fails a test job on a failure, an error, a skip or no passed test, and `tools/nightly/pack_card.py` refuses a card with Pi firmware. It reads the FAT entries of every partition itself, so a hidden or system file, any case and any folder depth count, and it takes the firmware names from `tools/fetch_firmware.sh`. The README shows its badge.
- `tools/check_workflow_exprs.py` moves here from Pip-OS and adds a rule that every `uses:` names a full commit. `make check-workflows` runs it in CI and in each project that includes `mk/robco.mk`. The workflows pass values to scripts through `env:` and pin their actions by commit.
- `robco-ci.yml` marks the checkout and every submodule folder, at any depth, as safe for git in both jobs, then checks that git works in each. Before, git refused the checkout in the container with "dubious ownership".
- The harness plugin removes a passing test's `tmp_path` when the test ends. A test that fails or errors in setup, call or teardown keeps its folder. Set `ROBCO_KEEP_TMP=1` to keep every folder. A project that sets `tmp_path_retention_policy` itself keeps its own value.
- `rimg_seal()` and `rimg_pack()` in `src/lib/rimg_seal.c`: the sealer and the packer in C. A host test runs every vector of `tests/vectors/rimg/vectors.ini` through them.
- `tools/rimg.py` reads a PBM icon width or height as 1 to 9 ASCII digits, as the spec asks. It now refuses `+32`, `-32`, `3_2`, `0000000032` and a token with a vertical tab or a form feed with `io`, as the C sealer does. Seven new vectors check it.
- `.gitattributes` turns off end-of-line conversion for test vectors, golden images and byte-compared fixtures, so a Windows checkout with `core.autocrlf=true` keeps their bytes. `tests/tools/test_vector_eol.py` checks it for `tests/vectors/`.
