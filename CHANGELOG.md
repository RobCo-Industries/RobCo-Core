# Changelog

## Unreleased

- The nightly run gains the `core-head` pairing: every sibling builds on the planned RobCo-Core commit, in its image, and the tests run on `raspi0` and `raspi2b`. `both`, the default, plans `pins` then `core-head`, and either one fails the run. A red pairing does not skip the other one. The version table names the library commit and image of `core-head`. A stale sibling pin fails `pins` and `both` but not `core-head` alone.
- The nightly test jobs rerun their failed tests once with `pytest --lf`. `tools/nightly/junit_gate.py` takes the rerun file and labels each failed test `FLAKY` or `BROKEN` in an annotation and in the run summary. The job stays red either way.
- `tools/sfx_table.py --bed NAME` names a loop that plays under the other sounds. The header gives each one-shot's head CRC-32, its rest's length and CRC-32, the bed's name and the longest head. `--dump` writes each head and rest, `--wav` each one-shot over the bed, and `--check` sees a change of bed. It refuses a one-shot as long as the bed's first part and peaks that add up past 127. Without `--bed` the output does not change.
- The trace's `op=pcm` line ends with `loop=1` when the play loops. A play that does not loop prints the same line as before.
- `tools/audio_preview.py` moves here from Pip-OS, where it was `boot_sound.py`, so every sibling can turn a serial log's audio trace into a WAV file. Its output bytes do not change, except that it now repeats a play marked `loop=1` until the trace ends it, skips an `ev=audio` marker without `op=`, and renders a log of several boot stages one after the other, with a warning per change of stage, and rounds a plain play as the driver does. `--scale` now takes `nearest`, the default and the driver's rounding, or `cut`, the old one. `auto` is gone: it picked `cut` for a plain play, which the current driver rounds to the nearest step. Its engines `tools/voice_engine.py` and `tools/tone_square.py` come with it, and `tests/tools/test_audio_engines.py` checks their constants and sine table against the C.
- `tools/sfx_table.py` renders a sound effect model into 8-bit tables: C with each length, CRC-32 and the model's SHA-256, raw `.u8` files or WAV files. `--check` tells when a table is out of date. Every C name and file name it writes holds `sfx`, so none can be a name of C or the system. A run checks its whole plan before it writes: it refuses two files at one path, or one path as a file and a folder, by any spelling, link or case. It resolves each path once and writes only there. A missing field hides no other fault in the model. Output file names are lower case with one `.`, so each header gets its own include guard. It publishes all files as one and restores the old ones on a failure. The format and the synthesis are in `docs/spec/SFX_MODEL.md`.
- `tools/sfx_check.py MODEL DIR` checks that dumped `.u8` tables sound like their model. It compares the band power and the frame level of each table with a prediction from the model, within a tolerance for each kind of sound. The prediction includes the rounding of each sample to a whole step, so a quiet table passes too. Bands and frames have their own gain. The noise prediction covers the smearing of a short envelope and the comb of repeated hits. A sound with noise gets its band width and frame length from its effective duration and bandwidth, by its kind. A band or frame the model fills and the table leaves silent fails. A table that is mostly rounding is judged on its length and peak only. A frame predicted under one step rms is not judged. A sound name that breaks the generator's rule exits with code 2 before any table is read. A band or frame with too few independent values is thin: a gamma chance bound of one in a million judges it, and the line counts the thin values. A loop is measured on its own bins. An invalid model, or a sound too costly to check, exits with code 2. A sound with noise also gets a level check of its peak against the strongest expected rms, and a table that misses the model's power under 15 kHz fails. A one-shot whose noise puts nothing in the table is judged as tones only. A model nested too deep exits with code 2.
- The nightly run keeps no card it did not boot. `tools/nightly/boot_card.py` boots a snapshot copy of each packed card in its card job and checks the stage markers in order: the terminal card up to the UOS login screen on `raspi2b`, the Pip-Boy card up to the ROM's ready line on `raspi0`. The card is uploaded only when the boot passed and the card still matches `SHA256SUMS`.
- `tools/nightly/pack_card.py` fails closed. A folder with starting cluster 0, a chain that ends early or runs long for its size, a cluster out of range or used twice, a long name with no short entry, an invalid short name, a stray volume label bit, a FAT32 root cluster of 0 and FAT copies that differ now fail the job. Before, it skipped some of them in silence.
- The nightly run, `.github/workflows/nightly.yml`: every night it builds the five siblings at their default heads on their own library pins, packs the terminal and Pip-Boy cards and runs the whole-chain tests on four boards. `tools/nightly/plan.py` resolves the commits and image tags into one record per built repository, which the matrices, the summary and `VERSIONS.txt` all read, so the Pip-Boy row names the library and tag of the Pip-OS head it builds on, `tools/nightly/junit_gate.py` fails a test job on a failure, an error, a skip or no passed test, and `tools/nightly/pack_card.py` refuses a card with Pi firmware. It reads the FAT entries of every partition itself, so a hidden or system file, any case and any folder depth count, and it takes the firmware names from `tools/fetch_firmware.sh`. The README shows its badge.
- `PIPOS_ABI.md`: ABI 1.5 adds the call `sample_rate(hz)`, number `0x27`. It sets the rate of `sample` and `sample_queue` to 8000 or 37500 Hz and returns the rate set before. Any other value returns `-PIP_EINVAL` and changes nothing. A play takes the rate when it starts, and a queued buffer keeps the rate of the play it joins. The rate is 8000 when an image starts, and a ROM gets its own rate back when a holotape ends. The limit stays 65536 bytes: 8.192 s at 8000 Hz, about 1.748 s at 37500 Hz. `tone` and `play_seq` do not change. ABI 1.5 also adds `PIP_HW_AUDIO_MID`, bit 4 of `hw_flags`: the audio output rests at its midpoint, so a sample that starts and ends at 128 makes no step, and a tone is a centred square whose height follows the volume. It is set when `PIPOS.CFG` sets `[audio] system_sound = yes` and the rest ramp reached its end at boot, and it reads 0 with `PIP_HW_AUDIO` clear. Specified only: Pip-OS still reports ABI 1.4, returns `-PIP_ENOSYS` for the number and never sets the bit.
- A centred tone above half `ROBCO_AUDIO_TONE_RATE` now plays at half that rate. Before, `audio_tone(18750, ...)` on the 18750 grid wrote only `128`, silence, and higher pitches aliased. The half period is now at least one sample: `half = max(256, (rate * 128 + hz / 2) / hz)`. The build stops when `ROBCO_AUDIO_TONE_RATE` is under 16000, twice the highest note, B8 at 7902 Hz, rounded up.
- Tones after the `audio_rest_mid()` ramp: a tone is now a square centred on 128, made in the sample IRQ on the PCM engine, instead of the PWM's own pulse. Before, a quiet tone moved the mean level by up to 47 % of full scale at its start and its end, a thump at the midpoint rest. Each sample that holds an edge takes the mean of the two levels by the edge's place in it, with integers another tool can copy. The height is `(ROBCO_AUDIO_TONE_PEAK * vol + 50) / 100` steps, default peak 127, and the grid is `ROBCO_AUDIO_TONE_RATE`, default 37500. `audio_tone()`, `audio_beep()`, `audio_play()` and `audio_play_rtttl()` all take this path. The trace lines and the busy answers do not change, and `audio_rest_mid()` returns 0 in every state once the rest is the midpoint. A kernel that never calls `audio_rest_mid()` keeps the same registers and trace. New engine calls `audio_square_amp()`, `audio_square_start()`, `audio_square_acc()`, `audio_square_out()` and `audio_square_at()`. `examples/audio` prints `grew=` in the `rest` case. Not heard or timed on a board.

- `audio_play_voice()`: a note computed live in the sample IRQ from a table of spans, with no sample buffer. Each span holds its phase, phase step and its change, level and its change, and the gain of a second partial. The sample is a closed form of its index in the span, from a 1024-entry sine table whose CRC-32 is `05067686`, so a late IRQ skips samples with no catch-up loop. The play runs on the PCM engine like a sample play: one grid, the same end, the same stop rules. An `audio_pcm_mix()` overlay mixes over it with one rounding, after the volume. `audio_pcm_queue()` refuses a voice with `AUDIO_ERR_STATE`. The start checks the level and the phase step at both ends of every span. The trace prints `op=voice rate spans len vol crc t_ms`, then `op=pcm_end` or `op=stop`. New engine calls `audio_voice_check()`, `audio_voice_start()`, `audio_voice_span_at()`, `audio_voice_at()` and `audio_voice_out()`, and the table `audio_sine`. `examples/audio` gains the `pcm_voice` case and the `v` key, and `tests/target/test_audio.py` checks it. Not heard or timed on a board.
- `AUDIO_PCM_RATE_MAX` rises from 22050 to 37500, the PWM carrier rate in PCM mode: one sample per carrier period. At 37500 Hz a sample lasts 26.7 us, and 3 samples fill 80 us. The engine's 64-bit bounds hold at that rate, and the host tests check its grid for an hour of samples. A rate of 37501 returns `AUDIO_ERR_RANGE`. `examples/audio` gains the `pcm_top` case, 100 ms at 37500 Hz, and `tests/target/test_audio.py` checks it. The rest ramp stays 882 samples at 22050 Hz. 37500 IRQs a second were not measured on a board.
- The `audio_rest_mid()` ramp never moves the duty by more than its largest step between two writes. Before, an IRQ late past the ramp's end let the pin jump from a low duty straight to 128. Now a late IRQ skips samples only while the step stays that small, and otherwise the ramp takes longer. It always writes its last sample, so `op=pcm_end` reads `last=881`. The `op=pcm` line and the ramp bytes are unchanged.
- `audio_pcm_mix()` returns `AUDIO_ERR_STATE` when a one-shot play's last sample has sounded and its end IRQ is still due. Before, it returned `0` and printed `op=pcm_mix` for an overlay that never sounded. New engine call `audio_pcm_join_plays()`.
- `audio_rest_mid()`: the call plays a 40 ms ramp from duty 0 to duty 128. Once the ramp reaches its end, every silence the PWM backend writes is duty 128 at the PCM range. A sample that starts near the midpoint then makes no jump. A stop, a cut or a priority start before the ramp ends cancels it: the rest level stays duty 0 and a later call can retry. A kernel that never calls it keeps today's pin levels and trace. The idle pin then carries the 37.5 kHz carrier all the time. None of this ran on a board.
- `audio_pcm_mix()` and `audio_pcm_mix_busy()`: one overlay buffer added to the PCM that plays, clamped, before the volume. It also takes a play that waits for its tick. The trace prints `op=pcm_mix len crc t_ms` at its start, with a 64-bit time, so a loop past 71 minutes keeps it right. The overlay and a late queued buffer start at the play's next grid sample that has not passed, so a late sample IRQ skips none of their bytes. Both are placed by a sample index on the play's one grid, not by a time, so at 22050 Hz no overlay byte repeats or is skipped, and late queues in a row do not drift. `audio_pcm_mix()` and `audio_pcm_queue()` refuse the ramp with `AUDIO_ERR_STATE`, and `audio_rest_mid()` returns `AUDIO_ERR_BUSY` while a stop waits for its tick. New engine calls `audio_pcm_join()`, `audio_pcm_join_us()` and `audio_pcm_chain_at()`, and the `last_n` field. `audio_pcm_chain_at()` compares the end in samples on 64 bits: a queue behind a play that ends more than 2^31 us away no longer switches at once or loops in the IRQ-masked call. The engine computes sample times on 64 bits, with at most two correction turns. Not heard on a board yet.
- The audio guide allows `audio_play_pcm()` and `audio_pcm_mix()` in a tick callback for short buffers, and says why the buffer must be short.
- `examples/audio` gains the `pcm_mix` and `rest` cases, and `tests/target/test_audio.py` checks them.
- `audio_pcm_scale()` rounds to the nearest step, a half step away from 128. Before, it cut toward 128, which flattened a quiet sine at any volume under 100. Every sample play at a volume under 100 now puts slightly different duty values on the pin. `audio_pcm_scale(255, 50)` is now `192`, was `191`.
- `tools/check_workflow_exprs.py` moves here from Pip-OS and adds a rule that every `uses:` names a full commit. `make check-workflows` runs it in CI and in each project that includes `mk/robco.mk`. The workflows pass values to scripts through `env:` and pin their actions by commit.
- `robco-ci.yml` marks the checkout and every submodule folder, at any depth, as safe for git in both jobs, then checks that git works in each. Before, git refused the checkout in the container with "dubious ownership".
- The harness plugin removes a passing test's `tmp_path` when the test ends. A test that fails or errors in setup, call or teardown keeps its folder. Set `ROBCO_KEEP_TMP=1` to keep every folder. A project that sets `tmp_path_retention_policy` itself keeps its own value.
- `rimg_seal()` and `rimg_pack()` in `src/lib/rimg_seal.c`: the sealer and the packer in C. A host test runs every vector of `tests/vectors/rimg/vectors.ini` through them.
- `tools/rimg.py` reads a PBM icon width or height as 1 to 9 ASCII digits, as the spec asks. It now refuses `+32`, `-32`, `3_2`, `0000000032` and a token with a vertical tab or a form feed with `io`, as the C sealer does. Seven new vectors check it.
- `.gitattributes` turns off end-of-line conversion for test vectors, golden images and byte-compared fixtures, so a Windows checkout with `core.autocrlf=true` keeps their bytes. `tests/tools/test_vector_eol.py` checks it for `tests/vectors/`.
